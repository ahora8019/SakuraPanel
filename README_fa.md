> **وضعیت پروژه:** توسعه فعال است. شاخهٔ اصلی مبنای پروژه است؛ ممکن است بعضی قابلیت‌ها همچنان در حال توسعه یا منتظر تأیید عملیاتی باشند. موفقیت CI به‌تنهایی ممیزی امنیتی محیط عملیاتی محسوب نمی‌شود.

SakuraPanel پروژه‌ای مستقل و مبتنی بر زیرساخت Cloudflare است که برای مدیریت قالب‌ها و کانفیگ‌های تولیدشده، انتشارهای نسخه‌بندی‌شده، کاربران و ارائهٔ اشتراک طراحی می‌شود. از گستردگی قابلیت‌های پنل‌های موجود به‌عنوان معیار عملکرد الهام می‌گیرد، اما هویت و معماری مستقل خودش را حفظ می‌کند.

## ✨ اصول پروژه

۱. **امنیت** — حداقل سطح دسترسی، بررسی مالکیت، نگهداری امن اسرار و رفتار امن هنگام خطا.  
۲. **پایداری** — مدیریت دقیق مهاجرت‌های پایگاه داده، بررسی‌های خودکار و انتشار کنترل‌شده.  
۳. **کارایی** — اجرای سبک و بدون سرور و دسترسی کارآمد به داده‌ها.  
۴. **سازگاری** — اعتبارسنجی ساختاریافتهٔ کانفیگ و بررسی سازگاری کلاینت‌ها.  
۵. **نگهداشت‌پذیری** — ماژول‌های روشن، مستندات و عملیات تکرارپذیر.  
۶. **تجربهٔ کاربری و هویت ساکورا** — رابط کاربری مرتب و سازگار با موبایل، با طراحی ظریف الهام‌گرفته از ژاپن.

## 🧩 معماری

```text
مالک / کاربران
      |
      v
Cloudflare Worker
  ├─ مسیریابی API و اعتبارسنجی
  ├─ احراز هویت / نشست‌ها / RBAC
  ├─ تولید کانفیگ، نسخه‌ها و انتشار
  ├─ ارائهٔ اشتراک و عیب‌یابی
  ├─ کنترل‌های امنیتی و رویدادهای حسابرسی
  |
  ├───────────────┐
  v               v
Cloudflare D1   Cloudflare KV
داده‌های برنامه  وضعیت محدودسازی نرخ /
                 کنترل‌های امنیتی
```

نسخهٔ فعلی برای اجرای بدون سرور روی پلتفرم Cloudflare طراحی شده و به VPS جداگانه یا سرویس endpoint اختصاصی نیاز ندارد.

## 🛠️ فناوری‌ها

- TypeScript
- Cloudflare Workers و Wrangler
- Cloudflare D1 برای ذخیره‌سازی SQL
- Cloudflare KV برای وضعیت اجرایی و کنترل‌های پیکربندی‌شده
- Vitest و بررسی نوع‌های TypeScript
- GitHub Actions برای یکپارچه‌سازی مداوم و استقرار کنترل‌شده

## 🚀 شروع کار

**پیش‌نیازها:** نسخه‌ای از Node.js سازگار با تنظیمات CI مخزن، npm و نسخهٔ محلی مخزن. برای عملیات وابسته به محیط، اعتبارنامهٔ Cloudflare و bindingهای صحیح D1/KV لازم است.

```bash
npm install
npm run typecheck
npm test
npm run dev
```

## 🤖 بات تلگرامی دیپلوی (برنامه‌ریزی‌شده)

قرار است پس از پایدارشدن Core، یک بات تلگرامی به‌عنوان رابط مستقل عملیات و استقرار ساخته شود. این قابلیت **در برنامه است و فعلاً به‌عنوان قابلیت پیاده‌سازی‌شده معرفی نمی‌شود**.

جریان کاری موردنظر:

```text
فرمان تلگرام از مالک مجاز
        ↓
بررسی مجوز + ثبت رویداد
        ↓
بررسی‌ها و تست‌های GitHub Actions + مرحلهٔ کنترل مهاجرت
        ↓
استقرار با Wrangler
        ↓
بررسی سلامت + ارسال نتیجه به تلگرام
```

فرمان‌های پیشنهادی: `/deploy`، `/update`، `/status`، `/logs`، `/rollback`، `/health` و `/version`.

استقرار باید به مالک مجاز محدود و مشروط به تأییدهای لازم باشد. اسرار فقط در محل امن نگهداری اسرار GitHub/Cloudflare قرار می‌گیرند؛ ارسال آن‌ها از طریق تلگرام یا ثبتشان در Git ممنوع است. بازگشت به نسخهٔ قبلی باید اثر مهاجرت‌های پایگاه داده را در نظر بگیرد و نباید راه‌حل خودکار و بی‌بررسی تلقی شود.

## 🗺️ نقشهٔ راه

برای اولویت‌های اجرایی به [نقشهٔ راه SakuraPanel](docs/sakurapanel-roadmap.md) مراجعه کنید. محورهای فعلی شامل موارد زیر است:

- تجربهٔ کاربری موبایل‌محور برای اشتراک و مدیریت

- پیش از انتشار، بررسی نوع‌ها و آزمون‌ها را اجرا کنید.
